# Набор для тестового задания Soup (AI Engineer): LoRA → merge → 4-bit → SHIP / DON'T SHIP

Модель `Qwen/Qwen2.5-1.5B-Instruct`, данные `d0rj/alpaca-cleaned-ru` (русский), бесплатный Colab T4. Всё запускается одним
ноутбуком `soup_task.ipynb`. **Срок сдачи: 13.11** (ответом на письмо, адрес team@trysoup.dev).

Код и шаблоны подготовил Claude Code. **Ни одного результата в файлах нет**: все числа появляются только после запуска,
в местах с пометкой `<<FILL FROM RUN: …>>`.

## Что в папке
| Файл | Зачем |
|---|---|
| `soup_task.ipynb` | Основной ноутбук: установка → данные → бюджет памяти → проверки Soup → обучение → merge → 4-bit → контрольные прогоны → проверка → `soup ship` → архив |
| `kit_common.py` | Общие функции ноутбука: логи с метками времени, сэмплер nvidia-smi, фоновый запуск команд с замером пиков памяти, подготовка данных, запасной стек (transformers+peft+bnb), проверки |
| `memory_budget.py` | Оценка VRAM/RAM **до обучения** по `config.json` модели; режим `--compare` сравнивает с замерами |
| `verify_trained.py` | Отдельный скрипт части 2: обучилась ли модель на самом деле и сохранилось ли это после merge и 4-bit |
| `silent_failures.md` | Таблица из 26 «тихих» сбоев по всей цепочке: как проверяется, ловят ли их проверки Soup, где доказательства |
| `report_template.md` | Шаблон отчёта на ≤2 страницы с местами под числа (если файла нет в папке, его текст передан отдельно) |

## Как запустить в Colab (по шагам)
1. Откройте https://colab.research.google.com → **Runtime → Change runtime type → T4 GPU** → Save.
2. Положите файлы набора в `/content/soup-task`. Два варианта:
   - из GitHub: в первой ячейке Colab выполните
     `!git clone <URL репозитория> /content/soup-task`,
   - или загрузите файлы вручную: панель «Files» слева → создайте папку `/content/soup-task` → перетащите в неё все файлы.
3. Откройте ноутбук: **File → Open notebook → GitHub** (или **Upload**) → `soup_task.ipynb`.
   Ноутбук сам переходит в `/content/soup-task` и ищет файлы там.
4. Запускайте ячейки **по порядку, сверху вниз** (или Runtime → Run all). Ожидаемое время на T4 указано в таблице в начале
   ноутбука, всего около 75–95 минут.
5. Долгие шаги (обучение, merge, проверка, `soup ship`) идут **в фоне**. Ячейка ждёт до 25 минут (переменная окружения
   `KIT_MAX_WAIT_S`). Если она написала «still running», просто запустите её ещё раз: она продолжит ждать и вторую копию не запустит.
6. Если шаг Soup упал, ниже есть ячейка **FALLBACK** с тем же шагом на transformers + peft + bitsandbytes. Она запускается
   только когда нужна. Причину падения не скрывать: лог лежит в `logs/cmd/<шаг>.log`.
7. Последняя ячейка собирает архив `soup_task_results_<дата-время>.zip` и предлагает его скачать.

Если Colab отключился, перезапустите среду и снова прогоните ноутбук сверху. Готовые шаги (данные, адаптер, merged и т.д.)
пропускаются, повторно ничего не обучается. Но после **полного** сброса среды (Disconnect and delete runtime) файлы пропадают.

## Важные замечания
- Версия Soup с PyPI (на Colab была v0.77.2) новее локальной документации (v0.75). Ноутбук сначала сохраняет `--help`
  всех команд в `logs/soup_help/` и подстраивается: например, `soup merge --adapter X` против `soup merge X`, и есть ли `soup data doctor`.
- В Soup по умолчанию `quantization: 4bit` (то есть QLoRA). В `soup.yaml` явно указано `quantization: none`: задание просит LoRA
  на fp16-базе.
- `lr: 0` Soup не принимает (`lr > 0`), поэтому в отрицательном контроле стоит `lr: 1e-9`. Отказ на `lr: 0` записывается в §3b.
- Ноутбук ходит в сеть только за pip-пакетами и загрузками с Hugging Face. Секретов и токенов не нужно, модель и датасет публичные.
