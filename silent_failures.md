# Silent failures: data → tokenizer & template → training → merge → quantization → inference

A silent failure is a run that **finishes without an error but is wrong**. For each one: what goes wrong, how this kit checks
it (notebook section → output file), whether Soup's built-in checks catch it, and where the evidence is.

**How the Soup columns were filled.** "Per docs/source" means the local Soup clone (v0.75.0, `docs/` and `src/`), cross-checked
against the **v0.77.2 wheel from PyPI**, the version Colab installs. Its `--help` was read locally: `soup data doctor` **exists** in v0.77.2
(`--model`, `--max-length`, `--show-mask`, `--train-on-eot`, `--output`), `soup merge --adapter` is a flag, `soup train` needs
`--yes` without a TTY, and `soup eval quant-check` exists. "Data doctor" = `soup data doctor` + `validate` + `stats` + `inspect`;
"pre-flight" = `soup doctor --config` + `soup profile` + `soup plan` + `soup train --dry-run`. Every Soup cell is marked
**to confirm from run output** until the logs in `logs/cmd/` and `outputs/fault_injection.md` have been read. The last column is
left empty on purpose: fill it from the run, and never from this table's expectations.

Legend: ✅ catches it (per docs/source) · ⚠️ partial / only if asked · ❌ no check exists (per docs/source) · ❓ unknown for v0.77.2.

## What this table does not cover
- Behaviour under sampling, multi-turn chats, long context (> 1,024 tokens), safety and refusals beyond Soup's bundled suites.
- GGUF/AWQ/GPTQ exports: only the bitsandbytes NF4 artefact is checked.
- Seed-to-seed variance: one training run plus controls, not several seeds.
